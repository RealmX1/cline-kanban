## 共用抽象与接入实现

### 会话执行、身份与能力

- 共用接口覆盖启动、恢复、发送、运行中干预、中断、历史读取、分支和能力查询；CLI、原生 App Server、ACP 分别提供实现。
- 区分 Task、Kanban conversation、原生 thread/turn/item、执行实例和消息投递身份。路由按当前主绑定及实际 session transport 判断，不按 agent 名称或默认通道推测。
- Agent-native peer 工具、宿主向会话输入和 ACP 会话控制分别描述；同一 root tree 内的 mailbox 不推广为任意独立 Task 间的通道。跨 Task 仍复用 Kanban 已有寻址与投递入口，不新增 peer 总线。
- 权限、Plan Mode、模型、工作目录和 Codex 存储归属沿用实际启动快照。恢复不重投首条消息，不把 Plan Mode 翻译成权限变化。
- 运行时持有唯一执行所有权，浏览器只订阅和操作；旧执行实例的审批与答案不能投递到新实例。存量独立 PTY host 接回同一代际，不重复启动；ACP 的恢复能力按自身证据声明，不冒充 PTY host 保活。
- 通过完整 facet 三元组更新摘要；历史重放不刷新当前活动时间，也不制造新的接受边沿。

### 两个最小原型

- 原生路径复用现有 App Server 控制代码，增加结构化会话事件映射。
- ACP 路径使用官方 SDK 与固定版本的 `codex-acp`；优先复用已有 adapter 实现，只补 RVF 所需的最小原生证据扩展。扩展必须操作 adapter 已持有的同一个 App Server。
- 按初始化结果协商协议与能力，不把 SDK 大版本等同于协议版本；自定义方法遵守 ACP 的下划线前缀与能力声明约定。精确 fork／Rewind 另行验证 adapter 扩展，不因支持普通会话控制就声称支持。
- Codex `0.164.0` 与 `codex-acp` `2.2.2` 仅是 2026-10-25 的历史核查组合，不能直接作为新的实施版本要求。实际开始原型时重新核对并固定 adapter、SDK、上游 SHA 和实际 runtime；两条路径显式使用同一份外部 Codex binary、模型、上下文及工具配置，形成可比较的版本清单。
- 原型显式启用且仅运行于隔离实例，不改变真实任务默认通道；新增会话级选择兼容现有 OMP 字段和旧会话记录。
- API 变更同时核对 `src/core/api-contract.ts` 与 `src/trpc/app-router.ts`；若新增独立 npm 包，同步接入 CI install/test。支持 Node 22 下限。

### 共用事件、消息投递与界面

- 两条路径复用现有 `AgentConversationChatPanel` 和共享 hooks，展示正文、工具输入输出、diff、附件、提问和审批；完整内容保留结构，折叠只影响展示。对现有共享组件补所需结构，避免再造整套聊天界面。
- 所有主动消息通过 `managed-task-prompt-delivery-coordinator.ts` 登记。沿用既有记录、幂等键、正文摘要及真实回执，dispatcher 不重复登记。
- 保留宿主解析的可信 actor、目标归属和非真人正文标记，不从 `source`、正文、native `role=user` 或协议发送者自报字段提升授权。协议结构化不替代授权核验。
- 只有 `after_agent_turn` 进入等待调度；即时消息和启动消息不占等待队列容量。显示标签不能改变后台让位语义。
- 协议请求返回、Agent 回合结束和原生消息接受分别记录；尤其不能把 `session/prompt` 的完成响应误当作即时接受证明。
- 断线或写盘异常优先只读补证；需要重试时沿用已有有界恢复机制。可能已写入的消息不盲目重发，不覆盖原失败记录。
- 同键查询复用原意图，不改变冻结正文、首次解析的目标或截止时间，也不因队列条目被清理而重建。确认未写入时才沿既有安全策略恢复；写入可能已开始或接受未知时，自动核查原账本、同代控制端点与可信原生记录，持久记录重试预算和可检测的恢复条件。只有新权限或无法消除重复风险的真实取舍进入人工决策。

## Rewind、外部工作流兼容与 CLI 回退

- Rewind 使用指定历史边界的 fork，保留原会话，读取完整分页并核验历史前缀。会话回退与工作区文件恢复分别建模，不能因 fork 成功声称文件已恢复。
- 原生 fork、checkpoint、前缀核验和精确独立输入作为通用能力提供；RVF 等外部 producer 自己绑定开审边界、run、handoff 和业务阶段。本任务不恢复 Kanban 内已删除的收尾协调器或恢复监督器。
- 两条原型输出同一套原生证据：执行归属、活动分支、精确消息身份与正文、独立 user turn 接受回执和分支边界。活动分支查询绑定当前实例及 nonce。
- 分别验证“通用原生证据可产生”“当前外部 consumer 已接受”“实际业务阶段完成”。先核查当前 consumer 契约，不沿用旧版本的 TUI 身份假设；不伪装 `codex-tui`，不绕过归属校验。
- 外部工作流引用及观察快照不授权执行。缺少自动 Rewind 能力时，只暂停依赖它的动作；机器证据自动补查，确证未提交后可按既有策略有界恢复，已可能提交的未知结果不盲重发。
- 主会话交接与人工 Rewind 共用现存绑定及串行门禁。外部 producer 通过通用 API 尊重这些门禁。CLI 回退前完成旧执行所有权交接；无法确认已退出时，不并发启动第二个写入者。
- 确定尚未发送的消息可以转交 CLI；可能已发送的消息先补查接受证据。回退保留原生历史、启动权限、模型与存储归属，不静默新建空白会话替代。
- 如需修改 RVF 仓库，本轮原型阶段先提供精确 fixture、拒绝原因及接口差异，另行明确该仓库的实施归属；不直接编辑无关 checkout。
