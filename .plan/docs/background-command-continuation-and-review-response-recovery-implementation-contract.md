# 后台结果接续与 Review 响应恢复实施合同

来源：用户明确批准附件 `approved-plan.md` 并要求实施，视为 PLAN-READY。

- 能力：多个后台结果独立、幂等接续；全部工作结束后经既有完成事件进入 Review。网关中断后，Review 操作通过有限权威查询恢复界面。
- 范围：所属执行服务、共享终端投递门禁与恢复证据、完成事件/facet 链、浏览器共享 tRPC 与 Review 操作，以及回归测试。
- 边界：不更改 Stage 或外部 API 契约，不新增调度器，不重发结果未知的移列动作，不改动 `b1c53` 现场，不提交、同步或部署。
- 验收：其他工作运行或等待时就绪结果各接续一次，只释放自身等待；保留输入单飞、草稿、Stop、人工待答和身份换代门禁；失败与重启不重置预算、不重启后台工作；旧完成事件不覆盖新回合。
- 网关验收：纯文本/HTML 502 与连接重置显示可读错误；移列响应丢失时最多查询三次，每次 8 秒，退避 400/1200 毫秒；读到 Review 则采用权威快照，无法确认则显示结果未知并释放操作入口。
- 风险：网关连接重置的底层原因未知；本次只修复应用侧错误处理和状态恢复。

## 实施切片与验证

1. 后台接续：先补多执行互阻、失败恢复与门禁回归，再修改共享服务和终端投递；运行 guarded 定向测试，覆盖现有完成状态链。
2. Review 响应恢复：先补非 JSON 错误、响应丢失、有限回查和无重发测试，再修改共享 tRPC 与 Review 操作；验证主看板、Focus View 和跨项目共用路径。
3. 综合验收：前后端类型检查、Biome、隔离构建与浏览器故障注入；收尾幂等注册真实实例部署后验证项。
