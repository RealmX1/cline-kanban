# 任务编辑器的创建提交与恢复

创建完成以运行时确认卡片持久化为准。普通创建保存后关闭；连续创建清空正文、名称和附件并保留设置；创建并启动在关闭后继续处理关系和启动；创建、启动并打开在保存后立即进入任务详情。

## 提交身份与职责

共享 `TaskEditorDialog` 保留创建与 Backlog 编辑的同一套字段。创建时 `use-task-editor` 只准备新卡快照，ID 仍来自运行时的全局分配池，不乐观发布未确认卡片，不把新内容写回旧卡。

`taskEditorCreation.submit` 先验证页面 nonce、无 CLI 行动者声明及原用户手势，再持久化冻结输入与授权快照。记录位于运行时 HOME 的 `task-editor-creation-submissions/<submissionId>.json`，包含完整任务身份、目标项目、关系草稿、启动意图、执行边界、失败历史和恢复条件。写入使用原子替换与 fsync。

提交 ID 在所有项目间唯一。重试携带同一份冻结输入；更换正文、设置或项目会被拒绝。新卡已持久化后，任何重试都不覆盖卡片现值。已有任务的字段更新与项目迁移只通过编辑入口进行。

浏览器将未确认请求保存在当前页签所属的持久镜像中。响应丢失时先查询原请求，没有受理记录才重投同一 ID；保存已确认则释放这份镜像。表单会话身份和输入快照保护下一张草稿，快照包含本轮已采纳的项目和分支，以及关系草稿、撤销项和未完成详情。刷新后只向空表单回填原冻结正文、名称和附件，不覆盖后来输入。

未受理的原请求在浏览器恢复后自动补送，每轮最多三次；固定轮询只查询，连接恢复、online、回到前台或源项目 stream_reconnected 后才重新开启补送轮次。批量创建逐项确认并保留尚未保存的项；明确放弃时删除剩余批量列表，已发送请求继续保留身份并核验，不能恢复已放弃的表单。

## 后续步骤与自动恢复

运行时复用新卡持久化、关系批量提交和卡片启动能力。卡片保存结果按完整身份独立写入提交状态，不受保存后立即 Stop、搁置或关闭的影响；资格门禁只阻止后续关系与启动。关系完成后才允许启动。任务详情通过 `listForTask` 展示未完成步骤，`retry` 只恢复原操作。关系提交沿用稳定的 `modelingSubmissionId`，其账本事件另带原创建授权的提交 ID 和受理时间；重启不制造新的用户手势。

保存接口明确成功后，先持久记录原完整身份的保存事实，再检查当前身份与执行资格。后来换世或删除仍保留 `cardPersisted=true`、`identity_conflict` 与失败历史，不重建原卡、不覆盖新一世、不启动 Agent；保存抛错且没有可信证据时仍保持未确认。创建、启动并打开在确认状态为身份冲突时不会按裸 ID 自动打开新一世，迟到确认继续保护后来输入。

每轮最多三次尝试。依赖未变化时不再执行；任务、关系端点、配置、Agent 可执行文件或运行时世代变化后自动开始新一轮。损坏记录保留原文件并报告，不阻止其他提交。已完成提交不再反复读入完整冻结正文。

每次执行检查完整身份、当前位置、Stop、搁置和关闭状态。显式 Stop 单独持久化，沿账本的一世身份覆盖全部曾迁入项目；在中间项目 Stop 后再次迁移也不能抹除停止事实。搁置等资格门禁恢复后自动接续；删除或同 ID 换世时禁止旧请求复活或覆盖卡片。

启动准备失败可以重试。`runtimeApi.startTaskSession` 的内部 `beforeAgentProcessLaunch` 回调必须透传到实际 transport 启动边界，在进程可能启动前持久化标记并再次核验执行资格。PTY 进程内 spawn、PTY host 重连后的 spawn 请求与 ACP 子进程 spawn 都在异步准备结束后执行门禁，自动续跑不保留这次创建的回调。标记之后发生中断时，先从卡片的真实启动记录或运行时实际拥有的活体摘要补证；ACP 连接尝试留下的 startedAt 与失败摘要不能单独证明启动。有启动事实就不重发 Initial Prompt。仍无法确认则保持 `waiting_for_evidence`，等待原会话证据更新，不以再次启动冒充核验成功。

## 旧草稿

旧 `createdTaskId` 只用于迁移恢复记录，不能成为创建表单的写入目标。缺少原始快照时，只能沿同建模提交的已受理冻结记录补证，不能借当前裸 ID 的卡片猜测原 incarnation；缺证时保留原草稿及未知状态。核验卡片完整身份和账本后，原关系、原建模提交 ID 及未完成详情保存到原任务记录。未记录的启动意图保持未请求；没有原始手势的关系等待用户在任务详情明确确认。旧草稿中相对原卡快照新增的正文或名称保留为新建草稿，当前表单已有的新输入优先。

卡片持久化前，关系预览始终使用虚拟草稿根；已保存卡片的详情按完整限定身份读取。创建表单不展示“已创建，尚未完成提交”的恢复横幅。

## 验证

- `task-editor-creation-submission-service.test.ts`：独立建卡、冻结输入冲突、响应丢失、三次重试、运行时恢复、Stop／搁置、换世、启动补证与旧草稿迁移。
- `task-editor-dialog.interaction.test.tsx`：保存即关闭、慢保存与重复点击、迟到回调、连续及批量创建、旧草稿和项目切换。
- `task-editor-creation-submission-real-browser.integration.test.ts`：HOME、CODEX_HOME 和 CODEX_SQLITE_HOME 隔离的打包运行时与 Playwright。通过 `KANBAN_TASK_EDITOR_CREATION_PACKAGED_CLI_PATH` 指定隔离构建；`PLAYWRIGHT_BROWSERS_PATH` 指向浏览器缓存；证据目录由 `KANBAN_TASK_EDITOR_CREATION_BROWSER_EVIDENCE_DIRECTORY` 指定。

本变更不恢复历史任务内容，不包含 Git 提交、分支同步或部署。

## 跨项目启动展示

已确认保存且请求启动的创建记录投影到跨项目条目的可选 `taskEditorCreationAgentStartupProgress`。投影与 Running 分组共同核对完整身份并优先采用真实会话；仅创建 Backlog 不受影响。首页、Focus View 与 CLI 查询共用分组，创建提交阶段变化即时广播。目录指纹缓存共享一轮读取，已完成提交不因后续状态变化反复解析。详见 [Running 展示与验证记录](research/new-task-running-startup-visibility-implementation.md)。
