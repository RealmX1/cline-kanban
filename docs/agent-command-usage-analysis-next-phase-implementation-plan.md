## 实施合同

- **能力**：用一个仓内按需入口重放已有记录，输出目标族证据、语义对照与完整成本字段；避免每次调查重新手写长分析脚本。
- **范围**：现有Python标准库分析原型的工程化、固定输入清单、合成回归、私有证据/安全汇总分离、有限目标抽样、受控对照与指引。
- **非目标**：新运行时采集器、通用脚本执行器、多harness全量适配、后台轮询、自动调优、新业务查询API、真实部署或生产收益承诺。
- **复用优先**：先迁入并收敛已有解析和统计函数，不从零重写；不因为语言不同而把Python AST分析全部改成TypeScript。
- **依赖**：工具作为开发分析入口，使用Python 3.11及以上和标准库；不增加Kanban运行时的Python依赖或新npm包。现有Node 22下限不变。
- **边界**：只读原始记录，绝不执行其中的命令或脚本；写入只发生在明确的分析产物目录。真实Git测试仍遵守仓库fixture规则。

## 输入与目标命令

仓内入口已接线，具体使用边界与输入示例见工具文档：

```sh
npm run analyze:agent-command-and-inline-script-usage -- \
  --input-manifest ./agent-command-usage-input-manifest.json \
  --analysis-artifacts-directory ./agent-command-usage-analysis-artifacts
```

输入清单版本定为 `agent-command-usage-analysis-input/v1`，包含：

| 字段 | 含义与约束 |
| --- | --- |
| `schemaVersion` | 固定版本，未知版本明确拒绝。 |
| `analysisWindow` | 含起点、不含终点的UTC窗口，不再在代码里写死七天日期。 |
| `sourceInputs` | 显式文件/目录、格式、材料摘要及覆盖说明；目录输入启动时展开为文件清单并冻结。 |
| `excludedExecutionSelectors` | 明确排除本次分析执行的匹配范围；路径匹配只说明过滤范围，不从目录名推断任务身份。 |
| `baselineReference` | 可选、带摘要的首轮汇总与版本，用于口径桥接，不冒充本轮重新观察。 |
| `goalSampleSelection` | 有界、确定的样本选择条件及上限，不能随机换样本后直接比较。 |

只支持两种已知输入：Codex原生已完成 `CommandExecution` JSONL；首轮已有私有规范记录JSON。后者若只覆盖直接CLI或内联脚本子集，必须保留子集分母，不能据此重新宣称观察到全部33013次执行。压缩转录及其他harness不在本阶段强制支持范围，未覆盖情况明确输出。

优先用已冻结的私有记录推进目标分析；确需原始行补证时再在已声明来源内读取，不重扫无关历史或用户HOME。原型中的个人绝对路径、默认日期和任务排除条件须移入本机私有输入清单，不固化进工具源码或合成fixture。

## 输出与信任边界

每次观察保留独立持久目录、输入材料摘要、分析器版本、窗口、过滤条件及恢复来源。固定输入重放的规范记录、聚合和抽样顺序应确定；时间戳不参与语义结果比较。

| 输出 | 保存内容 | 公开边界 |
| --- | --- | --- |
| 私有规范执行记录 | 原始来源定位、执行/命令材料、解析状态和证据 | 不进仓库fixture、不嵌入HTML。 |
| 私有目标证据目录 | 样本归属、支持/反例、版本及结果契约 | 不自动公开执行ID、任务/原生会话ID、原始路径和正文。 |
| 聚合汇总JSON/HTML | 白名单指标、分布、归因类别、适用范围和不确定性 | 禁止直接序列化私有对象；错误类别也不得带参数值或原始stderr。 |
| 目标对照结果 | 固定fixture身份、前后步骤、结果及副作用、完整成本 | 合成材料可入库；真实私有材料只保留在任务持久目录。 |
| 第三阶段候选目录 | 最多5个目标族的排序、已有替代、缺口与进入条件 | 不把候选当作用户已批准的新API。 |

退出约定：`0` 表示声明的输入已完成分析，记录级未知仍须明确保留；`2` 为输入清单或参数无效；`3` 为必要来源缺失等导致证据不完整并已保存部分结果；`1` 为内部失败。下游不能把 `0` 单独当作“所有目标均识别”或“优化成功”。

## 解析、去重与目标归属

1. 复用现有shell词元跨度解析、内联脚本提取、CLI识别和错误分类。保留支持范围；复杂或未支持语法标成未知，不猜执行结果。
2. 原生执行事实才计调用。帮助、复合shell、输出重定向、文档heredoc中的示例、引号内换行/管道和业务正文分开处理。
3. 识别重复来源副本时保留原事件身份与材料。相同文本的真实重复执行不能去掉；相同ID而内容/上下文冲突不得后写覆盖，须保留冲突及来源。
4. 文件所在会话、cwd、裸任务ID或同一AST骨架不能自动证明原始执行归属、相同业务目标或重试关系。
5. `operationGoalFamilyId` 表示可审阅的目标族；`operationGoalObservationId` 仅在原生明确关联或受控fixture明确绑定时有值，否则为 `null`。
6. 现有“十分钟内同目录同命令成功”只保留为启发式线索，不转换成真实修正次数或首次成功率。

初始目标族按结果契约划分：读取/筛选既有JSON、读取固定日志片段、查询任务并保存快照、读取精确绑定的评审证据、重复调查分析；必要的源码修改和业务正文生成单列。不能把“查卡”“查另一个任务”和“查最新任意评审”混为同一结果。

抽样上限60条，确定性选取并冻结清单；覆盖至少10个结构簇、明确CLI包装、非看板/归属待定、必要代码/文档正文及P95长尾。每簇至少2例、至多5例；如某类没有足够记录，保留真实不足，不造样本凑数。目录说明代表性边界，不将抽样比例外推到全部9542次执行。

## 成本与成功语义

| 指标 | 可计条件 |
| --- | --- |
| `authoredCommandCharacterCount` | 原始shell字符串，包含引号、路径、正文和重定向；计Unicode字符，不冒充token。 |
| `agentAuthoredInlineScriptCharacterCount` | 能明确提取的内联代码，未支持语法保持未知。 |
| `agentAuthoredInputFileCharacterCount` | 已观察到且绑定同一目标的准备文件；不可得为null，不能当0。 |
| `modelToolInvocationPayloadCharacterCount` | 仅有原始工具payload及可靠归属时记录；不能与内层command重复相加。 |
| `preparationToolInvocationCount` / `goalCompletionToolInvocationCount` | 有明确目标链或受控fixture时记录；shell子进程数和模型工具调用数分开。 |
| `correctiveAttemptCount` / `firstAttemptSuccessful` | 必须有同一目标身份与结果判据；仅时间邻近不够。 |
| `knownAuthoredCharacterSubtotal` | 只加不重叠的已知部分；任何必需组成缺证时，完整总成本仍为null。 |
| token、耗时、机会分母 | 只读可信实际观测；没有就保持unknown，不由字符数估算成收益。 |

每个目标先冻结结果、身份与权限要求、允许的输出差异和失败/副作用契约，再测长度。脚本工程化的一次性投入和后续重复调用成本单列；不可只展示调用命令变短而隐去准备文件。

至少完成两个受控目标对照：

- 查询/选择JSON字段或保存任务查询快照：保留完整结果需求、错误后不继续处理及既有产物保护。`> task-snapshot.json && ...` 可能在查询失败前截断旧文件；首轮成功路径的字符示例不能替代这项验证。
- 读取固定日志/既有证据：先明确按字节、Unicode字符还是行计量；`tail -c` 不自动等价于Python字符切片，选择“最近记录”也不等价于读取精确绑定记录。

对照可以得出“拒绝该短配方”。至少纳入一个短但不等价的反例；不能通过弱化结果契约、忽略旧文件损坏或只比较退出码来做出成功对照。仅运行合成fixture中明确编写的固定命令，不执行从真实转录抽取的脚本。

## 自动补证与跨重启恢复

| 情况 | 等价证据/动作 | 有界与持久状态 |
| --- | --- | --- |
| 原始路径迁移、文件轮转 | 先用摘要匹配的已冻结私有规范记录；必要时在清单声明来源内重新定位 | 每个材料指纹自动尝试一次；仍缺则部分结果与来源待证状态，不要求用户代查。 |
| 记录损坏、格式不支持、身份冲突 | 保留已完成记录、冲突与覆盖计数；回读原始事件或已有精确记录补证 | 不覆盖原失败，不静默丢弃，不让单条未知变成全流程停摆。 |

| 某原生替代工具不可用 | 使用已安装等价工具或将配方适用性标为不满足 | 不自动安装依赖、不静默跳过后称等价已证；继续其他对照。 |
