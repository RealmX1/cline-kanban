# 远程终端响应：实现与自动验收

任务 `ab5a3` 按用户批准方案，在 `497a5ef0f13f9b2afdbb01891cb53ead394d2477` 上实施。没有提交、同步、推送或部署。

## 已实现行为

- 终端 IO、control 与状态流共用 permessage-deflate 参数：1KiB 阈值、级别 4、禁用上下文复用、并发 4。未协商压缩的客户端仍可连接。
- ACK 高/低水位为 400,000/200,000 B，socket 为 256/64KiB；活输出继续保持 16KiB 分帧和原有字节顺序。解析完成的未压缩字节累计至 32KiB 或等待 8ms 后确认，旧双 socket 的批次不能扣减新连接的账。
- 隐藏页默认声明 `paused_output`；服务端 Agent、权威 mirror 和活动观察继续运行。连续输出观察租约及旧端兼容路径保留。恢复中途隐藏会取消等待，避免后台重连；非活跃任务暂停继续关闭。
- diff 初次读取、手动刷新、版本失效、轮询及自动重试都经过同一可见性门控。隐藏时保留已加载内容与条件版本，重显后合并为一次条件读取。
- 共享卡片领域层按会话集合和真实任务归属预分组，主看板、Focus View、置顶、预览及 PDV 的共用入口均覆盖；活动展示仍按有效活动签名复用。
- 项目切换只等待目标路径核验；其他项目后台核验并广播，重叠核验共用在途请求。尚未核验的项目使用既有 `project_path_access_could_not_be_verified` 原因，不能冒充可用。

## 分片恢复与兼容

新端在 control URL 声明 `restoreProtocolVersion=2`，服务端发送 `restore_begin / restore_chunk / restore_end`；没有声明能力的旧端继续使用 `restore`。没有持久数据迁移。

每片携带 `streamGenerationId`、`outputVersion`、`restoreRequestSequenceNumber` 和连续序号。快照正文按完整 UTF-8 字符分为至多 64KiB 的片，接收总量上限 64MiB。服务端逐片等待发送回调，客户端验证身份、顺序、字节总量和结束计数。完整接收后逐片解析，应用完成且新 IO 打开后才回 `restore_complete`；新协议的确认必须带完整身份，且服务端已发完快照。

隐藏暂停会递增该观看者的恢复序号并清零其未确认字节。输出版本与流代次都未变时，免快照重显的 `output_demand_state` 公布这个序号；客户端只在序号前进后改用它确认新输出，并取消尚未发出的旧批次。暂停期间到达的迟到帧不再确认。正在发送新快照时，序号仍只由 `restore_begin` 公布。

有效接收与解析进展续期，重复或过期进度不能续期。客户端空闲期限 5 秒、服务端 10 秒，两端另有每次恢复 60 秒总期限。恢复缓冲超过 4MiB、读取/发送失败或超时，只淘汰观看连接并重新握手，取消原先强开闸门后在未知屏幕上续写的路径。

同一恢复 episode 连续失败三次后保留画面和错误，等待 online、页面重新可见或工作区状态流重新连接再接续。恢复不重启 Agent、不重放用户输入；存量的独立会话续跑逻辑继续保留原资格判断。

## 自动验收结果

功能回归覆盖压缩协商、精确 ACK、共享多观看者背压、暂停及缓冲淘汰、新旧恢复协议、分片缺失/乱序、旧连接迟到事件、进度与总时限、隐藏中止恢复、预算耗尽与恢复信号。真实 Chrome/xterm 验证两万行历史、UTF-8/ANSI、alternate screen、原生鼠标模式及恢复后的输入和滚轮。

原生可见性验证使用独立 Chrome、原生窗口最小化/恢复及直接 CDP，未改写 `document.visibilityState`，也未启用 Playwright 焦点模拟。隐藏观察窗内 IO 帧数保持不变，输出来源继续增长，共享 PTY 暂停数和输入重放数均为 0，重显后完成新快照握手。实验入口验证后才启用默认值，并再次核验默认路径。

专项网络测量复用 c810e 的持续输出/回显形式和 3fed0 的 TCP 整形代理，补上按连接方向 FIFO 放行。基线冻结自本任务 HEAD，候选来自当前实现；均使用真实 node-pty、服务端 mirror、双 WebSocket、浏览器 xterm 和相同语料。两轮 A/B 与 B/A 覆盖 160/200ms RTT、配置均值相同的三角抖动、1/10Mbps、低/高输出及双观看者，共 24 场、216 次输入。

| 场景 | 基线暂停占比 | 候选暂停占比 | 基线回显抵达 p95 | 候选回显抵达 p95 |
|---|---:|---:|---:|---:|
| 160ms RTT，高输出 | 47.8–48.4% | 0% | 281–326ms | 165–197ms |
| 200ms RTT，高输出 | 54.4% | 0% | 319–323ms | 205ms |
| 同配置均值抖动，高输出 | 28.6–31.9% | 0% | 369–389ms | 203–204ms |

| 1Mbps，高熵输出 | 81.3–81.5% | 73.9–74.4% | 953–954ms | 2084–2097ms |

正常链路上的 200ms RTT/目标 600KB/s 场景通过暂停占比低于 5%、抵达 p95 不超过 300ms 的目标。高输出重复重绘的实际 IO 下载速率约从 273KB/s 降至 33KB/s；单纯放宽窗口没有计作省流。

最终补充在途 ACK 的恢复代次校验后，对 200ms RTT 场景再做两轮交替复验：4 场、40 次输入，候选暂停占比仍为 0%，回显抵达 p95 为 203.5–205.6ms。完整矩阵保存在 `terminal-transport-full-matrix-measurements.json`，最终复验为 `terminal-transport-measurements.json`。

容量不足时扩大窗口会增加回显排队，不能承诺相同延迟。重复重绘样本不能外推到所有 ANSI 输出。记录了数据抵达、解析回调和绘制三个时间点；xterm 的 render 事件可能先于 write 完成回调，二者不是同一条同步屏障。

探针主进程包含桥接、mirror、代理与 CDP 采样：高输出候选 CPU 约 14–23% 单核，基线约 9–12%，同时候选处理更多未压缩输出，不能把全部差值归因于压缩。候选单场 RSS 增长未超过 8MiB；短窗增量不是长期内存上限。抖动的配置均值相同，未测得精确配平的实际 RTT 分布。计时检查采用软告警与硬失败两档，专项矩阵不进入预提交。
