# Codex 异常退出后的会话恢复

## 事故与修复边界

任务 `1cf36` 在选择“清空上下文并实施”后，原进程以 `101` 退出。旧自动重启重放任务初始 `/plan` 提示词，创建了另一段规划会话，补充要求与已批准计划没有随重启带入。该次原生 `101` 的原因没有复现，保持未知。

Codex `0.166.0` 的隔离回环模型验证表明，正常选择清空上下文会新建原生会话，以完整批准计划进入实施模式；按该新 ID 续接后，模式与历史仍保留。修复针对 Kanban 的恢复路径，不冒充原生崩溃修复。

## 恢复行为

- Codex 自动重启把需求正文、图片与 Plan 起步留在首次启动，续接只按当前可信原生 ID 寻址。
- 重启参数中的旧 `resume` / `fork` 目标及启动正文不会覆盖新观测身份。模型、目录、权限覆盖及未知选项的不透明后缀继续保留。
- 主会话缺少身份或身份对应的转录暂未可读时，复用现有持久恢复请求与预算；同一证据最多三次，间隔十五秒。
- 可信 hook、独享原生端点、转录出现及存储目录变化可以提供新证据。补证不发送占位消息，也不生成批准记录。
- Stop、运行时退出、会话换代、责任或真实输入变化使旧恢复意图失效；自动重启的准备、原生宿主与 spawn 等待都继续检查取消资格。

旧 `side-session-native-identity-recovery` 持久目录继续兼容读取，避免升级后遗失请求或重置预算；代码模块统一为 `task-session-native-conversation-identity-recovery.ts`。

## 身份来源与只读补证

正常路径仍消费原生 hook 的 `session_id`。Codex 缺证时可以读取本代独享控制端点，要求端点的 conversationSessionId 与运行代际匹配，完整读取已加载会话分页，仅接受排除已知 fork 来源后唯一、ID 与工作目录匹配的会话。分页循环、重复 ID、多候选、目录不匹配与不可读状态继续保持未知，不按最近文件猜身份。

显式按 ID 换会话后，先清除旧身份，再登记只补证、不重启的恢复状态；本代真实身份确认后沿现有 summary 写入和持久化通路回写。

本次 `1cf36` 的现场恢复已通过原生 `/status`、完整转录和独享端点确认旧计划会话；用户随后授权回写，已经现有身份观测入口同时核验内存及持久摘要。该观测记录明确标注控制面来源，不伪装为 SessionStart hook。

## 退出证据

异常 Codex 退出在销毁镜像前记录 workspace、task、运行代际、退出码或信号、最新原生身份与终端末尾快照。文本最多四十行、16000 字符，复用轮转 journal：

`~/.cline/kanban/diagnostic-event-journals/task-session-abnormal-exit.jsonl`

镜像无法读取时快照为 `null`，不伪造现场。自动换代等待读取结束，并重新检查 Stop；诊断写入失败不阻止必要恢复。

## 验证

定向 guarded 测试覆盖退出 `101`、新身份取代旧重启目标、迟到转录、跨重启预算、主会话只读回写、分页唯一性与异步 Stop。真实 Codex 检查隔离 HOME、CODEX_HOME、CODEX_SQLITE_HOME，只连接回环模型，核对清空后计划与实施模式、原生历史和首发次数。

部署后的真实用户配置、PTY 托管及诊断与原生启动回执衔接由独立的自动只读验证定义观察。源码验证通过不表示已部署。
