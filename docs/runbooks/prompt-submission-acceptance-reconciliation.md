# 输入接受标记的核验与恢复

`pending` 是有效提交 hook 或程序化提交产生的候选；15 秒内尚无接受证明则成为 `unconfirmed`。两者都不是失败回执，也不授权重发。原始 Enter 只唤醒读取，Shift+Enter、bracketed paste 内换行和终端协议报告不产生可见候选。

## 正常接受与长会话

Codex 先读取最近回合的 `summary`，再读取从前驱到最新回合的 `full` 前缀；首次只取最新回合建立基线。`summary` 只包含回合首条用户消息，同回合 steering 的核验必须保留 `full` 路径。完整读取失败时，已有可信前驱之后的新回合首条输入仍可用 `summary` 核验。

`summary` 后备独立记住已报告的首条输入，完整读取的前驱与用户位置保持原值，恢复 `full` 后补出旧前驱的 steering 且不重放新回合首条输入。待补前驱位于后续页时，每次最多定位或完整消费一页：先按轻量页找到前驱，再按旧到新的顺序读取 `full`；书签只保存页游标与回合 ID 摘要，布局变化后自动重新定位。只有扫描到末页仍无前驱，才按 Rewind 建立新基线。分页补读不把旧工具历史计成当前活动。

已知未完的完整读取有独立续读调度，idle 与已 accepted 的标记不会停止它。取得新进度后按冷却期继续，同位置失败按 15 / 30 / 60 秒退避，耗尽后保留游标与真实未知；新的输入唤醒或会话身份更新可重新核验。dispose、身份更换与新 Rewind 清理旧分页调度；不跨重启恢复 live 活动游标，重启继续走持久候选的历史补证契约。

用户消息以原生回合 ID、消息 ID 和前驱位置去重，不与工具、推理输出共用 512 条活动预算。工具活动超过预算时暂停该活动投影，仍推进用户接受水位；预算恢复后的首次活动读取只建基线，避免把被逐出的旧工具活动重新计为当前活动。初始化、Rewind 或丢失前驱只建基线，不重放历史输入边沿。

候选保存 `submissionId`、来源、原生身份、可用的正文 SHA-256 和此前接受事件 ID。异步结果提交时再次核对候选与会话身份；原生 B 消息可以推进自己的真实活动，但不能确认正文不同的候选 A。程序化消息的 Queue 回执另有正文、前驱和投递身份核验，卡片接受状态不能代替它。

## 持久历史补证

冷启动时已有候选可能早于活动基线。补证只读取该会话绑定的 Codex 原生 JSONL：先核对 `session_meta` 的原生 ID、工作目录与 `cli` / `vscode` 来源，再核对 `event_msg.item_completed.UserMessage` 的原生 thread/turn/item ID、原事件时间及正文摘要。工具调用、`task_started`、压缩或运行状态都不构成用户接受证据。

有正文摘要的候选要求匹配摘要；旧候选缺摘要时，只接受提交后 15 秒内唯一的原生接受记录。多个可能匹配保留未知，更早的接受记录不能冒领后来的候选。历史记录证明的是当时的接受事实：进程后来退出、控制端点消失或会话后续 Rewind 不会撤销它；这些事实也不证明当前分支仍有后续执行资格。

每次最多扫描 256 KiB，持久保存文件身份、字节位置、元信息核验状态及最多两个匹配。超长记录逐窗口跳到换行；未能完整解析的用户记录仍不能被推断为已接受。转录替换或截断后重新核对归属，旧文件的匹配不能继承。

已核验身份与正文、但事件时间晚于本轮观察起点的完整用户记录也保留在匹配证据中，不随 EOF 游标丢失。唯一匹配须等原事件时刻到达后才可确认；等待不消耗缺证重试次数，由持久的 `nextCheckAtMs` 自动唤醒，重启后继续。单次等待不超过 Node 定时器上限，始终保留原事件时间。

扫描持续取得进展时自动续扫；无变化时按 15 / 30 / 60 秒重试，耗尽后 `nextCheckAtMs=null`，保留真实原因。新的输入唤醒、转录追加、端点身份更新及运行时重新接管可重新核验，不要求用户提供机器可读信息。原生读取共用并发、超时与冷却限制，不通过补发输入来探测接受。

历史补证经独立写点更新标记，保留原事件时间，不发布新输入边沿：不改变回合、移列、触发主会话交接、失效阶段目标、刷新 Cache warm 或改写 Queue 原有失败结果。主看板、Focus View 与跨项目精简行共用来源、时间和原因说明。

## 回归入口

根项目通过 `npm run test:guarded` 运行接受读取、恢复、observer、输入解析和交接回归；Web UI 运行两个卡片活动显示测试。真实 Codex 集成只使用隔离 HOME、Git fixture 和本地 HTTP 模型桩：

```sh
KANBAN_CODEX_NATIVE_RVF_CLOSEOUT_SMOKE_BINARY=/absolute/path/to/codex \
KANBAN_CODEX_PROMPT_ACCEPTANCE_EVIDENCE_DIRECTORY=/absolute/persistent/evidence \
npm run test:guarded -- --project runtime-integration test/integration/codex-prompt-submission-acceptance-reconciliation.integration.test.ts
```

该用例证明已结束回合的真实原生接受可在冷启动基线期间补证，且不发布新输入或刷新交棒与缓存；不会调用外部模型。
