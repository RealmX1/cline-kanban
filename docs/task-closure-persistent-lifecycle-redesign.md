# 正式结案的持久生命周期重设计

## 实现合同

- 能力：结案、清理、复开跨重启接续，同一请求重操作默认最多三次；相关修复确证后仅自动补一次。
- 范围：持久失败分类与恢复条件、归档复用、完整性凭据、安全冗余回收、取消及复开幂等、旧数据兼容、隔离验收。
- 不包含：恢复六个已取消请求、生产旧副本清理、外置存储迁移、提交、同步或部署。
- 验收：空间波动、PATH 变化及重启不补发次数；归档失败不累积副本；取消或身份变化不继续删除；唯一成果与成功归档不被回收。
- 影响面：`src/task-closure/`、任务卡片动作及运行时恢复入口、Git 快照、共享契约、历史显示、安装兼容检查与相关测试。

- 验证：guarded 定向与集成测试、运行时及 Web 类型检查、Biome、隔离构建；真实实例断言通过 PDV 定义登记。

## 持久状态与幂等边界

| 对象 | 持久真相 | 完成条件与恢复边界 |
| --- | --- | --- |
| 结案请求 | `operation.json`、原请求参数与完整任务身份 | `preserving` → `archive_verified` → `closed_cleanup_pending` → `completed`；验证前保留源与原列，清理失败保留已结案结果 |
| 自动执行机会 | `automaticRecovery` 和只追加的尝试回执 | 请求内默认三次；正常步骤共享一次机会，中断后重做相同步骤另扣一次；重启不归零 |
| 复开请求 | 独立 operation envelope 与 `reopeningRequestId` | 还原、移列、续跑分别保存断点；同 ID 参数绑定在完成后仍有效，取消的 ID 永不重放 |
| 取消 | 独立、只追加的 `cancel-lifecycle-request-<id>.json` | 先落盘再等生命周期锁；复制及破坏性入口反复核验，不能等待大拷贝结束才受理撤销 |
| 成功归档 | 不可覆盖的验证发布回执、完整载荷 SHA-256、Git 保留引用 | 实际还原验证、源一致性重验及文件与目录 fsync 后发布；删除源前再次核验 |
| 回收 | `unverifiedCandidateReclamation`、原来源清单与回收回执 | 仅删除已证明冗余且无引用的失败衍生物；取消后的证明与删除合计最多三次，在证明前持久扣次，断点不会丢失来源证明 |

结案历史继续只追加。修复受损归档使用独立 replacement 载荷和 `archiveRepairManifest`，不改写旧历史或原成功归档。新的读取和复开解析修复引用；旧回执仍可阅读。

### 失败与自动恢复条件

| 失败原因 | 机器检查与接续条件 | 次数约束 |
| --- | --- | --- |
| 实际余量不足 | 同卷可用空间恢复至冻结的复制／还原需求加 1 GiB 安全余量 | 只使用剩余机会；空间波动不补额度 |
| 暂时 I/O 忙 | 第一次等待至少 30 秒，后续至少 120 秒 | 总共三次，跨重启保存 |
| 来源改变、Git 元数据暂不可读 | 自动重读来源清单；相同有效清单稳定至少 15 秒 | 只使用剩余机会，不要求人再次改动文件 |
| 所属进程未确认退出 | 原 PID 世代、系统启动身份、当前原生观察及退出信号相互核对 | unknown 继续等待，不把 PID 复用或重启当成新机会 |
| 软链还原验证失败 | 从原失败路径和快照确认确实为 symlink，实测对应权限恢复能力 | 相关修复确证且证据变化后，耗尽请求仅自动补一次 |
| 持久化失败 | 同目标目录实测文件与目录同步 | 同一修复仅一次补试；持续失败停止大拷贝 |
| 归档完整性失败 | 当前载荷重新匹配原完整性凭据 | 修复证据及剩余次数符合时接续；损坏期间保留来源 |
| 暂存树出现独有工作 | 核对 HEAD、仓库归属、路径、内容及 index；允许已知载荷的中断写入前缀 | 无替代恢复来源时保留现场，不删除额外成果 |
| 新的 Stop 或取消 | 独立撤销原件和 Stop observationId | 禁止旧请求接续；新请求必须取得自己的身份与资格 |
| 未分类或证据不可读 | 持久保留原错误与未知状态，继续检查其他请求 | 不凭 PATH、普通版本号或空间分桶推断修复 |

监控扫描间隔为 15 秒，单飞执行。它在持锁区确认恢复资格，在锁外进入已有卡片命令串行器，避免与用户操作形成锁顺序反转。可恢复证据由机器补查，不新增人工必答门禁；无法证明的唯一成果保持受保护状态。

### 完成副作用后崩溃

| 断点 | 等价完成证据 | 恢复动作 |
| --- | --- | --- |
| 归档验证完成，主 operation 未保存 | 独立发布回执及当前载荷 SHA-256 | 采用原 manifest，不再还原、不补发次数 |
| replacement 验证完成，修复引用未保存 | replacement 发布回执 | 补齐修复引用，继续核对来源 |
| 复开已还原到目标目录，完成回执未保存 | 目标 HEAD、index 和工作文件与归档一致 | 补记还原完成，不覆盖重新产生的工作 |
| 源已删除，清理回执未保存 | 原来源路径缺失且成功归档仍完整 | 补记已完成的删除，不再申请删除机会 |
| Agent 已启动，复开完成回执未保存 | 当前运行时中的所属活会话及启动时间，或已持久提交的复开事件 | 补齐历史与完成状态，不重复启动 Agent |
| 未完成的相同步骤 | 没有上述等价完成证据 | 按持久次数和具体恢复条件决定是否重做 |

Stop 标记与 observationId 同次原子提交。复开只能撤销请求建立时观察到的旧 Stop；之后发生的新 Stop 不能被旧授权清掉。启动前后均重验，必要时停止本次启动且归属匹配的会话。

## 载荷身份、体积和保留

每请求固定使用 `preserved-git-working-state-payload`；修复使用 `preserved-replacement-git-working-state-payload`。目录名只表示载荷身份，是否验证成功由 manifest 和独立发布回执决定。验证工作树与复开还原树各有固定路径，失败不会新增 `preservation-attempt-N` 目录。

归档和还原上限按来源估算并冻结在请求中。文件、index、对象包写入核算逻辑字节；对象包流式限额。请求保留上界为两份归档额度加一份还原额度，超额即停。载荷目录、实际 Git 对象目录和 Git common 元数据目录分别解析真实路径、按设备去重，共用卷锁、准入及 ENOSPC 恢复证据；对象目录软链到其他卷也不能漏掉元数据卷。其他应用仍可能消耗空间，实际 ENOSPC 继续进入持久等待，不能用外部波动补额度。已发布归档的廉价接续不要求重新预留完整复制空间。

成功归档长期保留，不设按年龄删除。等待修复的候选保留到能复用或能证明安全回收；来源漂移、未知归属、独有成果和旧归档继续保留。取消后的新协议失败载荷，仅在来源仍匹配原清单、无成功发布回执、无 operation／修复／历史引用时自动回收。回收前保存完整来源清单，删除中断即使原目录清单已丢失，也可用回收回执续接；证据不足不尝试删除。

回收证明绑定候选目录实例，并逐项检查当前内容。对象包只与原 HEAD 及受覆盖 index 在来源重新生成的只读 pack 流比较摘要，不创建派生索引、pack 软链或 Git 原子写入暂存；输出以候选大小及 30 秒限额约束，异常时等待本次 Git 进程关闭。pack 布局变化或内容不同均保守保留，不把摘要不一致解释成冗余。证明开始前持久保存回收回执；取消后的证明失败或硬退出同样消耗既有回收次数。

这些保留义务以恢复证明为边界，不引入按小时到期的自动清除。旧 `preservation-attempt-*` 不属于自动回收范围，本任务也没有删除事故副本。
