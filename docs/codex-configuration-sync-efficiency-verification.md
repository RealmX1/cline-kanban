# Codex profile 同步效率与规模核验

核验日期：2026-10-29。优化前固定候选为 `b9d389f86331e5d2cf3e1fa1a7e257151abbcffa`，原工作区 62 个变更文件与其逐字一致。本轮只实现恢复目标过滤、无变化观察免写盘和查询/执行分离；不增加索引、分页或接口字段。

## 方法与证据

使用三个合成样本，分别隔离 `HOME`、`CODEX_HOME`、`CODEX_SQLITE_HOME`。writer 使用真实目录及绑定核验，历史由合成字段和目标组成；填充历史 `previous.value` 的 ASCII 字符串以校准总体字节数，不复制用户配置。此样本用于比较算法和读写次数，不代表生产字段长度分布。

同一物理样本分别恢复相同持久快照，再交替执行优化前/后版本；每次测量有 25 秒预算。统计实际状态读取次数与字节、正文写入和字节、文件及目录 `fsync`、原生请求、续接检查与实际续接、writer × 历史比较和耗时。超时保留已采集的部分计数，不算完成或通过，也不据此推导精确加速倍数。初始校准样本含待绑定记录，不属于空闲状态，原始结果另存后排除并重测。

持久证据目录：`~/.cline/kanban/cross-task-handoff-artifacts/cline-kanban/12fbc/profile-sync-efficiency-verification/`。`benchmark-results.json` 为 32 项结果（其中 8 项基线超时）；测量脚本、隔离 bundle、合成快照、进度和逐项日志均保留。bundle 仅为测量导出既有展示投影并统计历史比较，没有向生产源码加入探针。

小规模连续十次稳定扫描：读取从 880 次降至 80 次，正文写入从 10 次降至 0 次，`fsync` 从 20 次降至 0 次。总量对齐和扩展样本固定四个 `pending_next_start` 目标时，优化后均为 16 次读取、4 次恢复检查、0 次实际续接；终态历史增长不增加逐目标读取。恢复检查仍保留既有完整持久化（4 次写入、8 次 `fsync`），本轮只对无变化观察短路。

总量对齐样本优化后三次连续查询：3 次读取、0 写入、0 原生请求、0 续接，合计 340 ms；四页面并发查询：4 次读取、0 写入，合计 284 ms。相同基线查询均在 25 秒预算内未完成。扩展样本对应为 518 ms 与 734 ms。计时含本机调度和缓存波动，主要验收依据是确定性调用次数。

## 样本代表性复核

`b9d389f86331e5d2cf3e1fa1a7e257151abbcffa` 是优化前已验证的代码候选，可用于比较本轮代码增量。它不是当时部署版本；合成负载也没有重放真实日常使用。此前将 8.9 MB 一档称为「现场规模」不够准确：它只对齐了总体字节、writer 和历史数量，并人为加重了目标密度及字段长度。

2026-10-29 19:13 UTC 的真实状态只读快照共有 173 个 writer、3,002 条历史；其中 32 个为未退役的原生 writer，历史目标数为 0，设置列表候选为 219 条。对应压力样本则是 168 个未退役原生 writer、2,662 个终态历史目标、2,662 条列表候选。旧值编码字节数中位数分别约为 202 B 与 2,270 B。该真实快照不是原测量时刻的快照，不能倒推原时刻也没有目标；32 个可扫描 writer 也不等于 32 个正在运行的 agent。

补充对照仅清空同一压力样本的历史目标，其余 writer 和长字符串保持不变。优化前后都读取 8 次；正文写入从 1 次变为 0 次，`fsync` 从 2 次变为 0 次，单对计时约为 828 ms 和 531 ms。该单次对照说明原超时对人为目标密度敏感，也说明免写盘收益仍存在；不能据此报告真实日常延迟或稳定的百分比收益。原始记录见持久证据目录下的 `baseline-representativeness-visual-explainer/`。

## 剩余热点及后续建议

| 开销 | 总量对齐的压力样本 | 扩展规模 | 结论 |
| --- | --- | --- | --- |
| 单次扫描 writer × 历史比较 | 447,216 | 1,788,864 | 仍为乘积遍历；后续可评估按 writer/字段构建内存索引，避免改动持久 schema |
| 完整状态响应 | 8,982,950 B | 18,160,795 B | 查询分离没有缩小响应；历史分页需要单独定义游标、排序和刷新一致性 |
| Chromium 完整设置页渲染至两帧 | 约 4.0 秒 | 约 8.3 秒 | 优化前后几乎一致；后续优先评估历史按需加载或分页，再判断虚拟列表 |

总量对齐样本单次状态读取/解析约 31 ms、展示投影均值约 33 ms、响应序列化约 11 ms；这些开销未因本轮优化消失。浏览器测量使用当前真实 React 组件、生产构建 CSS 和两版生成的合成响应；已确认全部 2,662 / 5,324 个历史条目进入 DOM。合成长字符串会放大布局代价，以上是受控样本观测，不能直接当作真实用户界面的延迟承诺。原始结果见 `browser-history-rendering-results.json` 和截图。

## 行为回归与边界

确定性回归覆盖：固定待恢复数与终态历史增长、稳定十次观察无正文写入、无 `revision` 变化的元数据落盘、首次创建和 schema 迁移、原子替换后目录同步失败的幂等重试、查询并发、后台恢复阻塞隔离及并发明确操作。无浏览器启动、目录监听、五秒补扫和到期由运行时独立推进；前端沿用首次加载、重连补读、旧响应淘汰与精确到期隐藏。

运行时/Web 类型检查、相关 guarded 测试与 Web 测试、Node 22/24、隔离构建、真实 Codex（本地合成模型）及打包 Chromium 均作为交付核验。精确执行结果和新增 RVF 状态写入同一持久证据目录，不用旧候选的评审冒充本轮覆盖。原有两个部署后验证按相同 ID reconcile；真实运行实例的待验状态保持，部署不在本轮优化范围内。

扩大检查还覆盖 hook 来源恢复和跨设备目录身份两组 40 项测试。固定基线已有 16 项失败、24 项通过；首次优化候选因遗漏四处显式扫描增至 20 项失败。补齐两组查询依赖的扫描调用后，恢复为 24 项通过、16 项失败，失败用例名称集合与基线完全一致。保留全部原断言及原始日志，未把基线失败计为通过，也未扩大到旧 profile/身份行为修复。主相关组的 122 项和 Web 49 项另行核验。
