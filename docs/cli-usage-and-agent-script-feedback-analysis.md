# CLI、Agent 临时脚本使用负担与反馈循环

本任务已实现首轮短入口、当前任务查询与调用指引，并提供独立的交互分析 HTML。用户补充明确：优化对象包含非 Kanban 原生命令的长 Python 等脚本，其中一部分仍在完成看板信息查询或操作。因此，不能把问题缩成原生 CLI 参数过长。

## 实现合同与边界

- 能力：减少可由机器确定的启动和当前任务身份样板；简单 JSON 查询、证据保存和日志读取给出可复制替代；复杂重复分析落为持久脚本。
- 范围：运行时入口、PTY / ACP 环境、任务查询、角色提示与命令参考、相关测试、统计与 HTML、部署后待验登记。
- 范围外：自动改代码或自动部署的反馈调度器、通用脚本执行平台、新结构化输入协议、缩短业务命名、删除理由或授权门禁。
- 验收：不同 shell / 路径含空格与特殊字符 / 固定 Node 参数 / 安装重新链接 / 重启复用；跨 cwd、协作归属、身份缺失与冲突；统计边界自检、真实浏览器交互与任务预览显示。
- 授权：用户已明确要求实施所给计划；后续补充扩展了分析口径。没有提交、base 同步、推送或部署授权。

直接 CLI 起头的 shell 执行共 1,441 次，含 315 次帮助；59 次 shell 非零。27 次有明确解析错误：未知 `--project-path` 9 次、遗漏关系理由 8 次、未知 `--json` 4 次、未知 `--task-id` 3 次，以及其他 3 次。

## 已实现的首轮优化

### 固定运行时的启动入口

macOS / Linux 在运行时启动时，先清除继承的旧绑定，再原子生成内容寻址的 POSIX 入口，并向新 PTY / ACP 会话注入 `KANBAN_RUNTIME_BOUND_CLI_EXECUTABLE_PATH`。入口绑定实际 Node、Node 参数及解析后的 CLI 路径；`--import`、`--loader` / `--experimental-loader` 与 `--require` / `-r` 的模块参数在运行时 cwd 解析为绝对路径或 URL，区分 ESM / CJS 导出条件并保留自定义 `--conditions`。入口执行不切换调用者 cwd；引用时保留双引号。不同安装互不覆盖，重新链接全局安装不会改变已有入口，运行时重启复用相同内容。

入口写入失败会告警并保留原完整前缀；下一次运行时启动可重建。已有会话不会自动获得新环境，Windows 保留原调用方式。持久入口不等于保存了 Node / CLI 安装本体，原路径仍须存在。

### 当前任务查询

`task get-current-task` 复用 `task get` 的返回结构，使用 `KANBAN_TASK_ID`、`KANBAN_PROJECT_PATH` 与 `KANBAN_TASK_CONVERSATION_SESSION_ID`，核对运行时快照中的会话归属。协作会话返回宿主卡片，切换 cwd 不改选任务。缺失、冲突或失效时明确报错，可用显式 `task get` 查询；不从目录猜身份、不自动跨项目改选，也不赋予新权限。

示例由 207 字符减至 65：

```sh
"$KANBAN_RUNTIME_BOUND_CLI_EXECUTABLE_PATH" task get-current-task
```

### 减少非原生长脚本

命令参考与任务提示现在明确引导：简单查询优先原生命令；完整证据用重定向保存，JSON 字段用已安装的 `jq`，日志末尾用 `tail`，文件查找用 `rg --files`。`&&` 保留失败后停止的行为。复杂脚本写入持久位置并复用，不反复重写到工具参数中。

HTML 中“保存当前卡片完整快照并展示字段”的等价改写示例，Python 包装为 829 字符，原生命令加 `jq` 为 211 字符。它是示例比较，不是部署后生产收益，`jq` 也不是 Kanban 的安装依赖。

已有文件输入与相对路径继续复用；关系目标、理由、证据、幂等键和资源映射不省略。没有为了少写命令新增一套通用 JSON 查询语言或任意脚本平台。

## 反馈循环草案

默认流程：**使用 → 找卡点 → 提出改法 → 确认修改 → 复测**。当前交付是分析器、报告与指引，不是自动修复或后台调度器。

| 指标 | 记录口径 | 当前状态 |
| --- | --- | --- |
| 命令与代码负担 | 完整 command、内联代码、固定样板、身份与业务正文各自字符数 | 历史字符可测 |
| 准备与外移成本 | 准备文件、转义、额外工具调用、脚本复用次数 | 历史关联不完整，保持未知 |
| 同目标成功 | 首次成功、修正次数、完成同一目标所需调用数 | 需稳定目标关联，待生产观察 |
| 使用机会 | 适用任务数、替代入口、可发现性 | 分母未知，不用低调用判断无用 |
| 版本与因果 | 工具 / 指引版本、shell、Node、原始错误来源、同覆盖对照 | 作为联合分析维度，不直接推断因果 |
| token 与时间收益 | 实际 token 和端到端耗时 | 未测量 |

建议每个目标观察保留 `operationGoalObservationId`、原生执行 ID、会话与宿主身份、工具和指引版本、来源定位、重试链及未知原因；这些是后续设计字段，尚未新增为生产契约。查询不得因缺少度量而阻塞业务执行。

机器缺证先复用原始记录、成功 JSON、重定向结果及精确版本补证。保留未知及恢复条件，只暂停依赖该证据的判断。相同身份 / 版本证据到达或下一窗口可复测时再接续；不能把未知写成成功，也不能把机器可查的信息默认交给人必答。
