## 实施合同

- **能力**：从声明的原生执行及已审阅结果材料，区分调用、独立结果观察、分析器版本、进程退出与对照业务状态。
- **范围**：既有分析输入增加可选的 `executionResultReviews` 文件引用；将自包含且摘要绑定的回执/结果文本与执行ID及command摘要关联；只增加现有JSON/HTML中的白名单反馈。
- **非目标**：通用目标推断、新运行时API、后台采集/调度、自动修改、Issue投递、提交或部署。显式审阅关联不成为用户授权，也不冒充原生显式业务目标身份。
- **证据**：已有5次实际分析调用指向3个观察和3个分析器版本。首次调用进程退出0，但对照未完成；同一观察的恢复/复用不会成为新的独立支持。它们属于开发验证工作流，分析输入为合成材料，不能冒充自然生产收益。
- **验收**：ID、command、材料摘要、观察身份、分析器版本与结果摘要一致才计关联；重复副本去重，同ID冲突保留待证；按执行次数和独立观察分别统计，不跨版本推出收益。缺证保留部分结果并继续独立分析，冻结材料可恢复且原失败留存。原始命令、路径、ID、正文及stderr不进公开输出，输入不执行。
- **落点**：原分析入口/manifest校验、结果审阅模块、私有冻结产物、原JSON/HTML及guarded测试；不新增npm入口或依赖。
- **风险**：调用方提供的审阅材料只做完整性与关联校验，不是签名认证；业务目标语义、真实准备成本和生产效果继续unknown。
- **验证**：先红测，再最小实现；原guarded回归、根typecheck、TS Biome、真实声明输入重放及浏览器/Task预览自动检查。

## 输入与信任边界

主清单可带 `executionResultReviews: {path, sha256}`；路径相对主清单，摘要必填。审阅文件使用 `agent-command-execution-result-reviews/v1`，上下文固定 `development_validation`，最多60条关联及180份材料。材料为 `materialTextsBySha256`，文本摘要必须与键一致；不会跟随回执中的路径读取其他文件。

每条关联包含 `executionId`、`commandSha256`、`analysisReceiptMaterialSha256`、`analysisManifestMaterialSha256`、`comparisonResultsMaterialSha256`。三份JSON材料分别证明回执观察ID、分析器版本和对照结果；manifest对结果文件的摘要必须一致。相同执行的冲突声明和相同观察的冲突结果均不后写覆盖。

`operationGoalObservationId` 仍保持原有未知语义。新增反馈只称为“显式审阅的执行与结果关联”，不据此计算首次成功率、修正次数、真实同目标成本或通用API资格。反例配方被正确拒绝是对照执行完成，不能算业务检查异常。
