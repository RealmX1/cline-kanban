# 任务专注视图与任务工作台

桌面 Focus View 的 Agent 区域和任务工作台支持「自动、左右、上下」布局。自动模式按浏览器视口判断：高度大于宽度时上下排列，其他情况左右排列。宽度不超过 768px 时继续使用手机页签布局。

上下布局保留左侧任务列表，终端默认占内容区高度的 60%。工作台内两个格位左右排列；左右布局时，工作台位于右侧，两个格位上下排列。两种方向的分隔比例独立保存，布局选择、比例和模块选择均纳入现有「重置布局」。

## 四个模块

默认格位为 Sessions 和 Prompts。每格标题处可切换模块，选择另一格已经显示的模块会交换两格；四个模块各挂载一次，换格或隐藏不销毁模块实例。Changes 暂时占用工作台区域，退出后恢复原配置。

| 模块 | 职责 |
| --- | --- |
| Sessions | 当前任务的主会话、协作会话、侧问会话及新建入口 |
| Relations | 当前任务的跨任务关系 |
| 探索地图 | 现有探索泳道图与本会话 Findings |
| Prompts | Prompts、Commands、Queue |

探索地图仍由 `agent-conversation-exploration-thread-graph` 建模，以任务卡作为 exploration 身份，可汇集同任务多个会话的轮次。本次只调整宿主布局与显示名称，不新增自由画布或维护作业。查看和换格不会触发付费维护。

## 新建会话与任务评论

Sessions 的「新建会话」按钮打开完整对话框，替代原创建页签和等价的 Add New。会话类型、Agent、上下文来源与能力限制沿用现有实现。当前页面内的创建草稿按项目与任务隔离，关闭或换格保留，创建失败保留，成功清空并选中新会话；浏览器刷新后不保证恢复草稿。

Comments 已从工具页签移出。`TaskCommentsDialogProvider` 由应用根提供共享评论控制器；`TaskCardBody` 使用卡片所属项目，缺省使用当前项目，因此主看板、Focus View、置顶卡、手机卡及跨项目卡共用入口，不需要分别接一套写入回调。永久删除的历史卡不提供评论写入口。

评论通过既有 `taskCardAction` 读取与字段更新接口保存，不走浏览器整板保存。读取失败时不提供空表单保存入口；保存失败保留内容并允许重试。保存前重读评论，只合并本次增删改，保留期间由其他入口追加的评论。该步骤不提供跨客户端读写之间的原子比较交换。

## 终端与验证

桌面布局切换复用原终端实例，容器尺寸变化由既有终端适配链路处理。首次后台启动尚无实测尺寸时，上下布局按任务列表之外的内容宽度和终端高度比例估算，不扣除并排 Diff 的最小宽度；左右布局保留原估算规则，已有实测尺寸仍优先。

自动化入口为 `web-ui/tests/desktop-focus-view-task-workbench.spec.ts`，覆盖 1080×1920、1440×2560、769×1024、1920×1080、格位交换、终端连接连续性、草稿保留、拖动及刷新恢复、手机评论触控入口与读取失败。fixture 拦截 API 和 WebSocket，不访问真实任务或关系账本。
