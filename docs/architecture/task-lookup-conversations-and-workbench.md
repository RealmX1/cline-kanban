# 持久多轮查卡与工作台

本功能由 `3346b` 承接，包含 `7a1dd` 的 Search 需求。共享 Context、材料采集与 headless 执行器来自 `a0401`；本功能不生成另一套 recap 或索引。

## 界面与任务身份

顶栏“AI 查卡”在现有工作台切换显示模式。已有 FocusTask 时保留左侧任务导航，中部和右侧切换为查卡内容；原任务界面保持挂载并隐藏，不停止任务进程。没有 FocusTask 时也能进入。Search 的“AI 查卡”传入描述、项目和列范围，通过同一查询服务提交第一轮。

点候选只预览，不修改 FocusTask。右侧默认两格为“查询会话”和“候选详情”，另可选择检索范围与共享执行器设置。点“打开任务”使用现有跨项目任务导航；再次进入查卡继续原会话。格位与大小偏好独立于任务工作台，横屏左右、竖屏上下，手机通过页签访问。

查卡会话不属于被检索任务，也不进入其 Sessions、worktree、facet 或关系生命周期。它是 runtime 持有的逻辑会话，底层每次模型请求仍是无状态 headless 调用。

## 查询与证据

查卡只做两阶段意图检索；不读取候选完整任务正文，也不执行内容搜索。

```text
一轮查卡
├─ 本轮范围 scope → 过滤项目与看板列
├─ 查卡问答历史 → 近期问答、较早摘要、按需回读本查询会话历史
├─ 第一阶段：范围内全部任务轻索引 → 按预算分批召回和归并
│  ├─ 短 task ID、Task Name、项目、看板列、本轮引用键
│  ├─ Task Description 短投影；没有简介就注明缺失，不回退完整 Initial Prompt
│  └─ 主会话最新 Task Progress 短投影
│     └─ 全局最终选择 0–10 张卡；不设最低数量，不强行补足
├─ 第二阶段：只阅读所选卡当前主会话的 Session Intent
│  ├─ 用户输入（包括计划要求和主 Session 旁支讨论）
│  ├─ AskUserQuestion / request_user_input 的问题与实际作答记录
│  └─ 每轮最后一次 Agent 答复；过滤过程答复、推理和普通工具输出
└─ 返回前核对任务身份、范围与概况版本 → 结果、覆盖缺口及绑定快照留档
   （这是服务端一致性检查，不是第三阶段模型检索）
```

旧路径重复发送 L1 全局目录、L2 本项目全量 recap、L3 追加变化和完整身份名单，历史失败输入为 1,291,034 字节。其他共享索引消费者继续沿用 L1–L3 合同；查卡独立使用轻索引，不加载 recap、通知归档或 Claude away summary，也不将完整 Initial Prompt 作为候选证据。

轻索引按每批 256 KiB 材料预算覆盖 scope 内全部任务，每批最多返回 10 项，分批候选在第一阶段内归并为全局最多 10 项后才读取会话。允许返回 0 项，此时不启动会话材料读取或第二次模型请求。首层只匹配意图：编号、概况和当前主会话进展；不能推断实现事实。

Session Intent 来源复用持久转录的稳定快照读取器，沿用原生身份、工作目录、分支和 history_base 核验。当前只读取卡片所绑定的主会话；材料携带会话身份、原消息 ID 和用户输入边界，不另造 turn 编号。按消息类型提取允许的材料，不让完整转录或工具正文进入模型。同一问答调用的后续结果按 `toolCallId` 关联为实际答案，结果保留原工具名也不重复归为提问。Agent 仍在执行或等待 question／plan_review／permission／needs_input 时，末轮只接受有原生 final 标记的答复；正常 review 交棒仍兼容没有 phase 的末次答复。每卡最多读取 64 页、16 MiB 消息材料，触及界限保留 `session_intent_scan_bounded`，不冒充完整覆盖。来源尚未绑定、不可读或快照失效时记录具体缺口，下次查询重新读取；没有完整任务正文回退。

较大的会话意图材料按 Unicode 边界分片，已知上下文拒绝最多三层缩批；单卡累计保留先前肯定、否定及修正，后文明确排除可以撤销早期匹配。普通缺省不冒充读取失败，真实失败与覆盖缺口进入模型、结果和持久诊断。候选来源由 runtime 注入，未来 Intent System 建模后可替换此来源。

查卡自身的历史与被查任务的正文分开处理：查询历史保留近期问答，长历史生成携带轮次引用和来源指纹的滚动摘要，可点名旧查卡轮次回读；这不授权读取任何候选任务全文。图片保持原问题归属及去重，文本预算不代表图片 token 预算。

限定任务身份在服务端保存完整映射。首层返回本轮引用键，第二阶段使用映射后的限定身份；返回前只重新核对 incarnation、名称、简介、进展及看板列。用户点击候选预览仍可在工作台查看原任务正文，该显式界面操作不会把正文补入查卡模型。

零候选是成功结果；来源缺失不等于讨论或功能不存在。认证失败、模型失败、超预算、取消和中断分别留档，不映射为空结果。Status、摘要与 Agent 自述不证明实现、合入或部署，查卡不写被检索任务或关系。

## API 与持久化

`support` 新增 `createTaskLookupConversation`、`listTaskLookupConversations`、`getTaskLookupConversation`、`submitTaskLookupTurn`、`cancelTaskLookupTurn` 和 `readTaskLookupCandidatePreview`。契约在 `src/core/task-lookup-conversation-contract.ts`，查询服务在 `src/task-indexing-support/task-lookup-conversation-service.ts`。

会话保存在 runtime home 的 `task-lookup-conversations/<conversationId>.json`；每批输入文本、限定身份映射及结构化结果另存于同名目录，避免可覆盖缓存破坏历史证据。结果绑定实际输入哈希；只有输入、没有结果的请求仍是未知，不推断为尚未调用。文件原子写入，单会话写入加锁；requestId 防止重复模型调用，同一会话同时只运行一轮。轮次变化在写盘后经全局 `task_lookup_conversation_updated` 推送，浏览器重连后重新读取，无浏览器轮询。关闭面板不取消查询。

新轮次持久保存 `owningRuntimeProcessInstanceId`。恢复仅中断所属实例已失活的轮次，沿用进程实例心跳的两分钟宽限期；新实例启动和读取历史不能中断仍存活的其他实例。缺少归属、心跳损坏或读取失败时保留运行状态并给出说明，不把未知状态称为重启。服务每 30 秒复核遗留轮次，同时转发共享历史的新 revision。runtime 关闭只取消本实例正在执行的轮次；取消也覆盖材料读取和 Context 准备。所有异步写回再次核对轮次状态与归属，重试只能由用户显式发起。

## 进度与失败诊断

运行阶段为读取索引、准备 Context、召回候选、阅读候选会话意图、核对任务身份与范围、保存结果。其中只有候选召回和会话意图解释两类模型检索。轮次保存阶段起点、最近真实活动、执行器设置、最近／最大文本输入字节数、批次覆盖与限长时间线；模型事件只提供活动摘要，不展示输入材料或推理正文。活动合并后每秒至多落盘一次，阶段切换与终态立即落盘；保留最近 200 条并计数说明省略量。超过 60 秒没有新活动只提示仍在等待，API 单次调用沿用 60 秒时限。

## 检索边界

本次提供意图查询，不保证定位所有内容细节。主 Session 中的旁支讨论若以用户输入、问题作答或回合最后答复出现，在该卡被首层选中后可以进入 Session Intent；未进入任务概况的讨论仍可能在第一阶段漏掉。过程工具输出、代码正文和其他未被允许的转录内容不会被本轮检索。

未来 Intent System 负责意图建模与查询，不能直接等同于内容查询。内容查询需委派后续的 agentic search（脚本 grep）与 Semantic Embedding + RAG，并返回所属 Task、Session 和原文位置。该能力明确不属于本次 scope；不会因意图检索没有匹配就自动读取全文。元信息维护协议见 `docs/task-description-and-work-progress.md`。

## 诊断与消费兼容

失败、取消与中断均保留停止阶段和原因码；执行器失败补充退出码、信号及脱敏限长的错误详情。所有状态都可展开检索记录和复制诊断，复制内容包含会话、轮次、请求与 runtime 身份，不含完整问题、任务材料或结果正文。请求模型与实际返回的模型身份分别展示，未返回的身份不能用请求别名补齐。旧历史缺少诊断时明确标为未记录。

浏览器按会话与 revision 合并更新，进度推流只重读当前相关会话，不重复读取整份历史。迟到的提交、取消和读取响应不能覆盖更高 revision；提交错误和各读取入口的错误独立保留。

执行器沿用 Context 项目共享设置，界面显示影响范围。模型用量单列用途 `task_lookup_conversation`；不宣称无状态进程能够命中缓存。Claude 认证状态与缓存验收沿用上游交接的未核实边界。
