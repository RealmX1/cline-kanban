# 查卡执行归属与持久提示词图片

## 多实例查询恢复

查卡历史保存在 runtime HOME 的 `task-lookup-conversations/`，浏览器单独记住选中的会话。历史会话可以跨重部署继续使用；运行中的模型调用则属于启动它的 runtime 进程实例。

2026-10-22 的现场记录显示，常驻进程仍然存活时，另一个实例的启动清扫把新查询改为 `interrupted`。隔离复现中，A 的模型调用正常结束后也无法回写结果，因为 B 已提前结束该轮。不能把界面的“已重启”文字直接作为进程确实重启的证据。

每轮查询记录 `executionOwnerRuntimeProcessInstanceId`。服务成功监听后才开启恢复检查；读取历史和定期检查复用实例心跳，只恢复归属已退出的轮次。心跳损坏或不可读时保留未知态，不沿用排队 prompt 的“读取失败按判死处理”规则。异常退出沿用现有心跳宽限期，优雅关闭直接收口本实例持有的查询。

后台恢复扫描只缓存每份历史的文件版本和运行归属，不缓存图片正文。未变化的文件只检查归属心跳；新建、修改或确认归属退出的会话才读取完整历史，因此可以发现其他进程的新轮次，也不会每 30 秒重复解析已完成的大图片历史。服务重启时重新建立该内存缓存。

无执行归属的旧记录不会自动结束。用户可以显式结束旧轮并重新提问；旧轮保留，新轮使用新的 `requestId`。取消操作不得把“不持有该执行”冒充取消成功。晚到结果同时检查轮次终态和执行归属。

## AI 输入组件

Kanban 自有的提示词编辑器复用 `TaskPromptComposer` 的选区插块、图片选择、粘贴、拖放和预览逻辑。保留专属补全的会话面板复用块插入运算与图片输入工具，不替换原生 Agent TUI。

已有结构化图片字段的入口继续使用 `RuntimeTaskImage`。只有文本协议的入口，将图片保存到 runtime HOME 的 `persistent-agent-prompt-image-attachments/`，以内容哈希去重，并把持久路径放进 `attached-reference-images` 引用块。编辑器把引用块呈现为附件条；消息、模板和草稿保存的文本自身携带引用，因此不需要为每套协议扩展图片字段。删除附件只移除该处引用，不删除可能仍被历史或其他模板引用的文件。

查卡额外把附件解析为 `questionImages`，随轮次和实际模型输入保存。Codex 使用原生 `--image` 参数，Claude 使用原生图片 content block；两阶段都接收图片，不依赖查卡执行器读取本地文件的工具权限。图片不进入跨查询共享的文本 Context。

多轮查询保留全部历史问题与图片上下文；每次执行按 MIME 与解码后的图片内容去重，重复提问不会重复传入同图。当前问题与各历史问题分别携带 `turnId` 和 `questionImageReferences`，其中 `imageInputNumber` 对应本次原生图片输入从 1 开始的顺序，原始附件 ID 与名称仍按各轮保留。当前轮未附图时，其引用为空，旧图仍只标注在相应历史问题中；模型不得自动把旧图当成本轮要求，但可用于显式追问。持久轮次与实际输入归档保留这两种身份，便于追溯。

## 验证边界

回归覆盖两个独立进程共享隔离 HOME、归属崩溃及宽限期、正常完成、未知心跳、旧记录显式恢复、图片协议和请求幂等。浏览器流程覆盖 localhost 与普通 HTTP、轮次边界、长问题折叠、图片附件、草稿跨刷新恢复及手机布局。

这些验证不等同于真实实例已部署，也不等同于正式 PDV 通过。
