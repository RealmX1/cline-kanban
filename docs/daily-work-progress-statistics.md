# 今日进展与里程碑庆祝

顶栏的今日进展显示当天进入 Validation、进入 Done 的不同任务数，以及任务内的人工 prompt 数。默认汇总全部已登记项目，展开后可切换单项目；该选择独立于看板的项目范围。

## 交互

- 点击顶栏摘要，在导航下方展开；手动打开后保持展开。
- 达成里程碑时向下展开 8 秒，可提前收起。60 秒内的多个成就合并为一轮反馈。
- 展开区占据页面空间，不使用弹窗、遮罩或焦点转移。手机 Focus View 中的导航、任务详情和按键栏不受其展开状态控制。
- 最近 3 项成果可以直接打开所属项目的任务。动效遵循系统减少动态效果设置。
- 首次加载、项目范围切换、历史回填和重连只对齐统计，不回放庆祝。跨页面的领取由服务端原子去重，并持久化。

## 计数

统计按浏览器的 IANA 时区与自然日分桶，包含夏令时日期。

| 指标 | 来源与规则 |
| --- | --- |
| 进入 Validation | 已提交的向前移列事件；同一项目、任务世代、日期内去重 |
| 进入 Done | 已提交的完成移列事件，包含直接收尾；同一任务世代当天只计一次 |
| 人工 prompt | 已确认任务身份关联的原生用户提交；首次需求、后续指令及任务内独立会话 |

Done 的 canonical 列 id 沿用 trash，对应 task_card_moved_to_trash_column。统计读取这一真实事件；恢复、初始化基线和永久删除不会被当成新的完成。进入 Done 不等于部署后验证通过。

人工 prompt 复用 submitted-user-prompt-transcript-record-parser.ts。统计额外排除已知程序化注入、自动通知、子代理记录、上下文注入，并对 Codex 双表示及 fork 继承记录去重。同一正文在不同时间的真实提交分别计数。无法确认时间、身份、格式或历史覆盖时，显示已确认记录及覆盖提示。

## 历史与里程碑

- 任务指标：1、3、5、10、20、50、100。
- 人工 prompt：10、25、50、100、200。
- 具备前 7 个完整自然日后，开放严格超过历史单日最高值、严格超过前 7 天日均两种历史成就；日均包含零活动日。
- 开始记录当天可能只有部分记录，历史比较从下一完整自然日开始。比较范围随项目选择一致变化。
- 历史纪录和超越日均，每项指标每天各庆祝一次；纪录继续增长时更新数字。

人工 prompt 的历史比较要求来源清单已读取、已纳入来源均读取完整，或有明确的分身排除证据。分身不形成历史缺口；不支持、无法识别、缺少已启动会话转录的来源仍显示部分覆盖。空来源清单不能证明历史完整，即使项目发现成功也保持未知；已确认读取完整且没有输入的转录可以贡献零活动日。

## 数据与接口

统计持久文件位于运行时 HOME 下的 ~/.cline/kanban/daily-work-progress-statistics/confirmed-work-progress-statistics.json。保存统计事实、转录读取偏移、覆盖状态和成就领取标记，不保存人工 prompt 正文。任务移列账本仍然是移列的真相源。

采集器按全局已提交事件序号追赶账本，按受限字节预算增量读取转录。历史读取主动让出事件循环；活会话与历史读取各有配额，坏文件不能阻塞其它项目。空闲时每 2 秒检查增量，统计变化经既有 runtime state stream 推送版本失效信号，浏览器不轮询。

- dailyWorkProgressStatistics.getSummary：日期、时区及可选项目 → 三项统计、历史比较、里程碑、最近成果、覆盖状态。
- dailyWorkProgressStatistics.claimCelebrations：原子领取已生成的实时庆祝事件，防止多页面和重启后的重复反馈。
- daily_work_progress_statistics_updated：全局版本失效消息；客户端按当前选择重新读取统计。

## 验证

领域测试覆盖日界、夏令时、任务世代、重复流转、零活动日、历史不足、双表示和持久化领取。隔离 HOME 的集成测试贯通真实移列账本、原生转录、HTTP 和重启恢复。浏览器测试覆盖桌面与手机的向下展开、8 秒收起、手动保持、焦点、切换范围与成果导航。

真实部署后的 PTY/hook 来源、运行时与浏览器的实际推流、自然工作中的计数及视觉表现，另通过本任务注册的部署后验证观察。
