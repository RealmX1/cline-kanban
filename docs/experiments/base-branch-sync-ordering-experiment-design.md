## 2. 四种角色，分别核验真实执行者

| 角色 | 工作 | Git 与会话边界 |
| --- | --- | --- |
| 实验构建者与 Overwatch：本会话 | 设施、数据备份、普通上下文投放、证据保存及对独立协调 Task 的监督 | 仅提交和同步自己的构建；不接管 Single Station、排序或逐项派发，不操作样本 Task 的 commit／merge／base-branch-sync |
| 独立 Sync Orchestrator Task | 获取指定候选及环境，决定合法顺序，向各原主会话发消息，派 Watchdog，核验回执后安排下一项 | 不代替被协调者执行 Git；不以改名后的中央 Git 控制器充当委派 |
| 原 Task 主 Agent | 在自己的工作上下文和 worktree 中完成交付整合，处理正常检查、冲突、修复与恢复 | 先 commit（尚有待提交交付时），再 base-branch-sync；已提交则核对后同步。使用原任务的正常权限与工具，不限制成只能补丁编辑的助手 |
| Watchdog SubAgent | 按 interval 只读追踪目标 Task／session／同步原件，向对应协调者汇总变化与异常 | 不替 owner 写源码、refs、index，不提交、不同步，不把自己的观察当作原 Agent 已执行 |

默认观察间隔先取 30 秒，可配置。轮询以现有 CLI／API 的廉价状态查询为主，状态变化或异常时再汇总；不每轮启动新 Agent。间隔不是回合、Token 或总耗时上限。

真实环境使用真实原主会话。隔离环境使用由同一备份恢复的对应原主会话副本、原任务上下文和 worktree；不能换成缺少原历史的通用新 worker，也不能修改生产 Task 的会话／worktree 指针来指向隔离副本。复制后的环境身份与原来源身份分别记录，不伪造生产会话归属。

第一级种子保存同一冻结点的 main ref／提交与可恢复对象、完整仓库和 base WIP／index、Task 卡片及 worktrees 的 HEAD／index／WIP、sessions 与原生历史、配置、依赖、发行物、评审原件以及来源映射和校验清单。种子不启动 runtime，不接受 Agent 写入，不用作可写依赖安装，不带活进程、socket 或在途执行资格。运行边界禁止第二级进程访问种子，恢复工具只读种子。

每次具体实验从同一已验收种子派生独立第二级实例，独立物化仓库／Git common-dir、HOME、状态、配置与依赖，重新分配端口、浏览器 origin 和控制端点。每份实例都有自己的 `refs/heads/main` 和私有 Git 对端；各 Task 的 baseRef 为 `main`，其 common-dir 必须属于本实例，因此 base-branch-sync 解析和推进的是本轮 main。私有 origin 的 main 与实例 main 起点一致，禁止连接日常仓库或 GitHub。实例之间和实例与种子之间均不共享可写文件、Git alternates 或硬链接；APFS 写时复制可用，但须验证 inode 独立与写入不回流。

验收同时核对种子标识、main 提交、各 Task 内容、原生历史前缀及隔离配置。重做一轮时从种子新建第二级实例，不以已经整合、修复或手动探索过的实例继续作为共同起点。12 张恢复卡包含父子交付，正式排序仍按去重后的 10 个交付核验资格，备份数量不等于正式入组数量。

真实使用环境一组仍按用户授权在日常 main 落地，不为该组把日常 base 偷换成隔离副本；其开跑前状态同样冻结为种子，离线对照据此派生第二级实例。当前供用户操作的构建实例也属于可写派生环境，绝不回写种子。

当前构建者驱动的旧副本已产生修复和新提交，不能作为本版正式对照的原始输入。新运行从保留的原始备份和新固定基线重建；不能把另一组已修复会话作为起点。环境修复、已知原候选缺陷与先验材料的可见范围对各方法相同，并如实记录。

## 7. 评价对象和账本

实验单元是「独立 Sync Orchestrator 的 ordering + 消息派发/等待 + 原主 Agent 实际 commit/base-sync + Watchdog」的完整工作流，不是中央控制器按排列重放 Git。

主要时间终点是整批在共同质量门槛下真实交回。单列 ordering、调度、源 Agent commit/验证/同步、机器等待及人工等待；未完成组报告完成比例和已用成本，不能被评为更快。构建基础设施落地和公共准备另报，不混入排序优势。

Agent Token 覆盖本构建主会话、所有协调者、Watchdog、原主 Agent、排序与必要评审；按真实会话／回合／response 身份去重。缓存输入属于输入子集，reasoning 若属输出子集不重复相加。失败和废弃尝试仍入账；缺失或矛盾保留 unknown／已观察下界，不当作零或账单费用。

跨任务冲突记录需求、接口、不变量、触发条件、双方交付与版本、复现、原始失败和修复。用 base、原候选及组合的对照剥离环境问题和原候选已有缺陷；不同方法的发现去重并验证后形成有限可观测并集，不称为所有真实冲突或总体 recall。

## 8. 构建验收与旧成果处置

- 证明真实 Git 操作来自对应原主 Agent 的工具／原生会话记录，身份与本环境 worktree 绑定；构建者、协调者和 Watchdog 没有代做。
- 证明未提交的交付先正常 commit，再 base-branch-sync；已提交的交付不重复提交。普通 hooks、验证和质量义务不得因实验被省略。
- 证明协调者只通过消息派发，Watchdog 按间隔只读观察；未知投递、容量故障、退出、重启和 main 前移均有可审计恢复路径，不重复派发／提交／同步。
- 证明真实环境原主会话未被隔离副本冒用，环境之间隔离，新的执行上下文未直接收到研究或另一组结果。
- 证明构建自己的 commit/base-sync 已先落 local main，实验 Task 后创建，执行批次基线包含该构建落点并妥善备份。

旧 DD679 隔离提交与 handback、BD273 的 WIP 恢复及静态复核保留为控制器校准。它们不作为本版排序效果、盲化或原主 Agent 自主整合成功的证据。已有两轮 RVF 是既有工具源码的历史覆盖，不自动覆盖改后的角色权限与派发机制；是否补审按实际新增风险判断，不为小增量自动增加轮次。

用户随后要求清理误解产生的实现。中央排序回合入口、只读 Git 的整合 worker、专属回合预算／恢复执行器及对应测试已从活动源码移除；删除前逐文件复制并核对摘要，原始执行、计量和评审原件不删除。私有 linked worktree 恢复逻辑提取为独立函数，保留完整工作状态与防覆盖检查，供独立 runtime 使用。备份、依赖恢复、纯用量解析及无模型历史核验继续保留。

优先里程碑：构建交回 local main → 独立协调者派发 → 一个原主 Agent 先 commit 后 base-sync 的完整闭环。只有闭环成立，再扩大运行；不能用准备项数量替代执行结果。
