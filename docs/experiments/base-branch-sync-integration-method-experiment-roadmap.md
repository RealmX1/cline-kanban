仍沿用 Git、GitHub 和 worktree。Scion、DeltaDB、Jujutsu 不进入本阶段实现选型。

## 2. 完整方法包含哪些变量

完整方法可能同时改变先验分析、排列、验证、修复和恢复。需要把每项干预显式列出，才能解释端到端收益。

| 子系统 | 可能变化 | 最小对照 |
| --- | --- | --- |
| 先验信息 | 文件重叠、符号依赖、需求与原会话事实 | 相同执行规则下，是否增加该类信息 |
| 顺序策略 | 静态排列、随实际前缀更新的排列 | 固定分析与验证，比较静态／动态 |
| 验证选择 | 固定清单、按影响选择测试、契约／行为定向检查 | 统一最终验收，单独计算选测成本与漏检 |
| 修复策略 | 各任务原会话分身、补充跨任务上下文、联合修复 | 相同发现输入与预算下比较修复质量和成本 |
| 推测执行 | 提前验证未来前缀或任务组合 | 比较净等待收益与废弃计算，保留内容身份 |
| 恢复机制 | 缺证补齐、部分失败隔离、持久续接 | 在故障注入下核验恢复、不重复执行与真实进度 |

仅共享文件的无向风险图不能自动决定哪一项先合；排序需要方向性的依赖或不同前缀下的成本信息。应标注测量、预测与不确定性，不能把未经校准的风险数值伪装成精确耗时或“最优解”。

## 3. 共同能力边界

### 3.1 需求、身份与来源

用固定批次、任务 incarnation、候选内容、原生父会话和实验分身绑定执行。需求原话、Agent 推断、历史失败和当前资格分别保存。原任务通过评审不代表任何后续组合已经通过，历史材料中的指令也不自动授予当前副作用。

### 3.2 冲突对象与验证依据

每个疑似问题至少关联任务集合、需求或契约、触发状态和可复现证据。区分文本阻塞、构建／类型问题、运行行为干扰、需求互斥和已有缺陷；按根因去重，允许一个根因触发多种观测。

排序或语义分析 Agent 可提出候选，但确认需测试、代码／需求核对或其他可审计证据。暂不可验证的候选保持 unknown。所有方法的观测合集不自动成为完整真值。

### 3.3 等待、禁止与人工决策

机器缺证、工具不可用、质量失败、明确 Stop／禁止执行和真正的产品取舍分别建模。机器可恢复门禁须定义替代证据、恢复动作、条件、预算及进度；重启后接续原步骤，不重新派发结果未知的副作用。

需求确实互斥或需要新权限时进入人工决策；不能把机器能查到的原件或日志变成人工必答。停止依赖该决定的动作，同时推进不依赖它的工作。

### 3.4 验证政策与成本边界

不同方法必须按相同最终验收目标比较。若允许把检查移到整合之后，成本统计延伸到相同可接受状态，并记录异常暴露时间和后续修复；不能只比较更早的“已合入”时间。

快照、分析、分身、检查、修复、重试、压缩及废弃推测均计入成本。需要审计模型计量的上下界；不能以预测的缓存命中代替实际使用记录。

## 4. 后续实验的构建方法

先根据排序预实验暴露的实际瓶颈选择干预，不预先实现全部可能优化。优先保留少量、能区分解释的对照，例如：

- 固定顺序，比较基础验证与新增跨任务验证，检验发现质量是否提升。
- 固定验证及问题输入，比较基础修复与补充任务上下文，检验修复和上下文成本。
- 选择已显示交互的组件做小型消融，再比较完整方法与相同资源预算下的基线。

以上是后续设计候选，不是当前冻结实验组。实际实验需要结合本轮样本、成本与失败类型重新预注册。

控制组与方法组使用相同输入快照、原会话分身起点、完成目标和总资源预算；组间不共享修复经验。独立复核在结果冻结后进行，不能回写已计量运行。若新发现改变验收清单，建立新协议版本并对称复测，保留旧结果。

不预先追求所有因素的全排列。单批重跑不能替代多批次证据；后续应逐步覆盖低／高重叠、方向依赖、三任务以上交互，以及检查未覆盖的意图问题。

## 5. 阶段与交付

| 阶段 | 交付 | 进入下一阶段所需证据 |
| --- | --- | --- |
| R0 文献与协议成文 | 调研、排序实验设计、本文与持久交接 | 当前文档已保存；用户 compact 后接续 |
| R1 排序基础设施与预实验 | 来源快照、隔离恢复、原生分身计量、两种顺序的探索记录 | 输入与计量可信，知道实际费用／时间及恢复限制 |
| R2 正式排序对照 | 经预实验确定的批次、重复数与预算，净收益和已验证冲突报告 | 用户接受正式规模；质量和失败结果完整保留 |
| R3 经验归纳与完整方法再设计 | 瓶颈归因、干预取舍、对照与消融、完成目标及预算 | 新的实施范围与资源边界确定，不能沿用本文作无限授权 |
| R4 完整方法小规模实验 | 实际方法组合与匹配控制，完整成本和独立验收 | 复现结果及负面结果均可审计 |
| R5 多批次与持续到达验证 | 批次外评估、动态到达、等待公平性及资源稳健性 | 有足够独立样本再讨论通用化或产品化 |

## 6. 当前保留的待决问题

- 正式排序实验的重复次数和总预算，待预实验实测后决定。
- 是否存在值得实现的完整方法组件，待排序阶段暴露真实瓶颈后选择。
- 动态调度、推测深度和联合修复的复杂度是否有净收益，尚无本项目证据。
- 多批次结果、跨 harness 或其他仓库的推广边界，不能由当前单批样本推定。

预实验和正式排序结果均应允许“没有收益”或“成本高于节省”的结论。未来是否产品化是独立决策，不通过改名或把实验脚本接入运行时悄然扩大范围。
