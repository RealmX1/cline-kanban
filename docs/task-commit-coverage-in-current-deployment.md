# 任务在当前部署版本中的提交覆盖

卡片目录行的「部署 N/M」表示：该项目最新成功部署记录的源提交历史，按既有 exact SHA / stable patch-id 一对一判据，包含 M 个已知自有提交中的 N 个。它独立于任务所在列、会话状态和 PDV 核对结果。

- 部分覆盖：例如 `部署 2/5`；全部已知提交覆盖：例如 `部署 5/5`。
- 未匹配到提交：例如 `部署 0/5`；无法可靠核对：`部署 ?`，浮层解释原因。
- 已确认没有已知自有提交时隐藏；尚未启动的 Backlog 卡不展示该指标。
- 分母复用保留提交统计的集合，包含待合入 base 的提交，排除已废弃的 amend/rebase 版本；已删除 worktree 的任务仍读持久来历。
- 新提交可以使 `5/5` 变成 `5/6`；部署回滚到更早源提交后覆盖数可以下降。同一 SHA 重部署仍更新部署身份和时间。

## 数据与刷新

服务端 `task-commit-coverage-in-current-deployment.ts` 读取部署组和任务提交来历，按 `workspaceId` 选当前部署，不使用全局 marker 推断其他项目。读取前复用既有 legacy 状态迁移入口：新文件缺失且旧文件存在时，将 `guided-verification-state.json` 原子迁移为 `post-deploy-verification-state.json`。匹配对照当前源提交可达历史，不能累加历次部署 delta 或用任务在 PDV 组中的存在性代替。

不可变 Git 检查有容量上限的缓存与并发限制；失败不缓存。只有确实需要 patch-id 等价匹配时才扫描从任务来历锚点共同祖先到部署源的区间。缺少部署记录、提交归属、Git 对象或完整历史时输出未知。

`RuntimeTaskWorkspaceMetadata.taskCommitCoverageInCurrentDeployment` 是兼容旧运行时的可选字段。主项目经现有元数据推流传递，跨项目经现有元数据查询传递；两者在 worktree 探针缓存之外更新覆盖。内容版本参与服务端和前端相等比较，核对期间部署变化则重算，避免下发迟到的旧部署结果。

卡片、Focus View、跨项目紧凑行和 PDV 实时卡片副本共用指标组件。悬浮或聚焦显示说明，点按固定浮层；不会转发成卡片导航或拖动。历史快照卡不叠加当前部署投影。

## 解释边界

「全部」仅针对保留的已知提交。匹配到提交历史不保证其功能效果仍存在，例如后续 revert 仍保留原提交的祖先身份；功能效果由部署后验证另行判断。无法由单提交 patch-id 证明的 squash 映射不会被推断为已部署。
