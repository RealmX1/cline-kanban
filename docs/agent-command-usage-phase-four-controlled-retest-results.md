# 第四阶段：首批配方的受控复测结果

第三阶段首批两个目标已落实为 [可复制配方](agent-command-json-and-task-snapshot-recipes.md)，继续使用原npm分析入口。四份结果契约、13个固定配方完成108次合成场景执行：9个配方满足各自契约，4个短但不等价的反例被拒绝。真实历史命令未执行，固定七天窗口没有重扫。

## 结果先于长度

必需JSON字段对照覆盖14类输入，保留null、false、0及各种空值，缺字段/空输入/坏JSON/多文档/错误根类型失败且无stdout，输入只读。命令样式参考已静态审阅的真实纯字段读取样本，具体执行只使用合成JSON。

当前任务快照的内联和任务局部持久脚本各覆盖16类场景：新建、替换旧文件、查询失败、坏JSON、缺字段、错误任务/项目/会话、多文档、两类symlink、目录、暂存创建与原子替换故障注入、查询进程终止。成功字节完整、模式600且文件身份变化；失败保留旧文件及其权限，无暂存残留。会话归属由原生查询合同承接，合成fixture不冒充真实部署验证。

保留原快照及Unicode精确证据两份历史契约，未将其旧通过扩大为新合同的证明。直接重定向、jq的false/null退出码混淆、按字节截Unicode及latest替换精确证据共4个配方被拒绝。故障注入验证失败传播，不声称覆盖所有文件系统、断电或恶意并发情况。

## 验证与恢复

原guarded入口执行固定输入/缓存恢复、静态解析/隐私导出、受控配方、发现性/归属四组回归；根typecheck及变更TS的Biome通过。新增配方按实际工具依赖报告状态，缺jq时Python对照继续，未执行的等价性为null。文档代码块与实际受控命令逐字核对，内联和落盘版本均执行同一组场景。

HTML同时展示首次及复用字符；浏览器自动检查配方结果、筛选、手机宽度与脚本错误，并在任务原生预览中核对同一修订。发布、浏览器实际显示及自动预览受理是独立事实，精确回执保留在任务持久目录 `agent-command-usage-phase-three-and-four/`。

首次落盘版本的合成PATH缺少sh，原失败观察与日志保留；修正绑定后以新分析器指纹生成新观察，不覆盖失败或把旧缓存冒充成功。后续中断仍复用原分析器的摘要核对和整体只读重放，不新增调度器。

## 接下来的真实观察

本批局部配方可按已知契约复用；没有足够可信同目标与跨任务归属，未新增通用CLI接口。生产观察须绑定实际可用的工具/指引版本和明确目标，先验证结果与副作用，再采集完整负担；不将两条合成输入当生产分母，也不由字符推算token或耗时。
