# Agent工作流成本与上下文有效性改进

减少Agent介入轮次、Agent输出和Agent输入，服务于降低Cost、减轻Context Rot带来的能力下降，以及维持或提升完成任务的能力。一次改进可以只改善其中一部分，同时保留代价、适用范围和未知项；已有成功也可随后续证据修订或回撤。

## 选择改进方式

先确定正在改善的工作及应保留的结果，读取当前判断需要的执行材料或既有摘要。相似代码不证明相同目标，工具调用数不等于模型轮次。缺失的token、费用、准备成本或能力变化保留unknown，不按0计，也不拿字符数冒充费用。

结合当前任务自主选择和组合以下手段，无固定顺序或硬编码场景路由：

- 使用现成工具，改善发现入口或指引。
- 精简、复用脚本，或直接把工具整合到既有脚本与流程；无需先创建独立脚本。
- 用Batched Scripts组合分散调用，或由合适的自动化步骤执行，减少不必要的模型介入。批处理不要求并行。
- 精炼直接返回的信息，保留按需详情。
- 保留现状，或调整、回撤此前改进。

不为了统一形式增加通用平台、复杂例子库或新的Agent步骤。具体工具、执行方式和信息需求由当前模型判断。

## 执行与信息返回

自动执行与向Agent提供上下文分别决定。直接返回当前有用的结果、必要状态和详情入口，避免重复注入无关全文。出错时直接给相关步骤、原因和必要诊断，不能只给“失败”；完整细节保留在可持久查阅的位置。需要再读详情时，其成本仍计入本次观察。

复用现有执行、结果归属和恢复能力。跨步骤组合时保留逐项结果与可定位错误，失败不能被整体成功回执掩盖。使用当前任务已有授权；本Skill不额外授予修改其他项目、提交、同步、部署或外发权限。

## 验证与记录

根据改动选择有意义的前后核验，检查所需结果、错误传播和副作用。分别记录可观测的轮次/调用、撰写量、实际读入量、费用与能力表现，不预设每项改进必须同时改善全部指标。减少轮次或token可以记为阶段性或单项成功，同时明确尚未证明什么。

需要跟踪改进时，读取[轻量记录模板](references/improvement-observation-record-template.md)，沿用当前项目已有记录载体；没有新的选择或证据时无需重复产出记录。只保留支持复查的摘要与证据入口，不复制整份转录或原始日志。

## 用实际应用改善本Skill

在其他流程中应用时，区分可迁移的方法与领域特定细节。用真实收益、代价、误用和未知项修订同一份Skill；不要把某个项目的一次经验直接变成全局规则。领域细节按需引用，不为每个项目复制一套元Skill，也不默认加载全部历史记录。
